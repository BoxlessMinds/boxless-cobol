The Punch Card Room

Before screens, a program was a box of stiff paper cards, one line of code per card, with holes punched in it. The card had 80 columns. COBOL still remembers them.

The 80-Column Card

IBM card format, introduced 1928

Each of the 80 columns holds one character. A character is stored as a pattern of holes in 12 rows. The keypunch machine also printed the character along the top so humans could read it. COBOL divided the card into zones, and fixed-format COBOL still uses them today:

The Card Deck Disaster

Happened in every computer room, eventually

A big program could be thousands of cards. Drop the box and your program is now in a random order. That's what the sequence numbers in columns 1–6 were for: a card sorter could put them back.

The low-tech backup: draw a diagonal line with a marker across the top edge of the whole deck. If the cards got shuffled, the stripe showed you which ones were out of place.

Why this repo still cares

A note from the curators

The programs in this playground use fixed format. If a line goes past column 72, the compiler silently ignores the rest. There's no error message. Your code just quietly loses its ending. So the repo's .editorconfig draws a guide at column 72, and the cobol-lint checker flags any line that runs over.

Dot says: If I end up in column 73, I'm invisible. Then your sentence never ends. Ask me how I know.
